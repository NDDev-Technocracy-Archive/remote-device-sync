# Source checks and test-target dependency ownership

`just check` runs only build-free checks: Just/rustfmt formatting, workflow
lint/audit, locked dependency/license checks, locked offline cargo-shear and
whitespace validation. None of these recipes builds or executes the product.
`just test` runs denied all-target workspace Clippy, nextest and doctests on a
build device or runner. Its optional feature argument is passed as one shell
argument, without interpolating it into command text.

Four direct edges used only by examples/tests move to dev-dependencies:
postcard and rds-sync in the benchmark crate, postcard in the relay, and Iroh in
the server. The shared included relay/server runtime fixture now consumes
explicit type/function imports declared by each integration target. This makes
its existing dependencies visible to source analysis. A first candidate removed
two genuinely used fixture dependencies after the scanner missed include!
contents; native compilation rejected that candidate. The corrected candidate
retains those dependencies and adds no checker ignore or warning suppression.

The final lock generated by the ordinary build toolchain is byte-identical to
the prior lock; no external package version is changed in this increment.
Build-free checks and denied cargo-shear passed. Cargo-deny retained its existing
multiple-version and yanked-package warnings under the unchanged policy; its
advisories, bans, licenses and source checks passed. Those warnings remain
separate dependency work, not waivers created by this recipe.

Physical Linux x64 qualification used snapshot SHA-256
`62bd6e5b69c7257a9b2d3c8677024ed2b90e11be4a4672c777b4be4e7506de5c`.
The standalone server binary built with both its default and owned-relay
features. The actual `just test rds-relay/owned-relay,rds-bench/transport-noq`
recipe passed denied workspace Clippy, all 1,017 nextest cases (three excluded)
and workspace doctests. The observed nextest version was 0.9.148; these results
do not qualify a newer test-runner executable. Native macOS CI remains its own
gate. No runtime resource reduction is inferred from dependency placement.
